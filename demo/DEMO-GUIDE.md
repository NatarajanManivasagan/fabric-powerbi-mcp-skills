# ContosoRetail — Demo Guide

Everything needed to run (and re-run) the 12-minute live demo in
`deck/PowerBI-Fabric-MCP-30min.pptx`, slides 13–17.

```
demo/
  ContosoRetail.pbip                 <- open this
  ContosoRetail.SemanticModel/       <- TMDL: 6 tables, 11 measures, 3 relationships
  ContosoRetail.Report/              <- PBIR: 2 pages + ContosoSignal theme
  DEMO-GUIDE.md                      <- this file
  demo-runbook.md                    <- timing, talk track, Q&A for the 30-min session
  list-mcp-tools.js                  <- ask any stdio MCP server for its tool list
  shots/                             <- fallback screenshots of both report pages
```

**The data is generated by M expressions inside the model.** No data source, no
credentials, no gateway, no internet. It refreshes anywhere.

## 1. What the model looks like

| Table | Role | State |
|---|---|---|
| `Date` | 2024-01-01 → 2026-12-31, marked as a date table | Clean |
| `Product` | 40 products, 5 categories, 10 subcategories | Clean |
| `Customer` | 60 customers, 3 segments, 8 countries | Clean |
| `Sales` | ~3,200 rows, seasonal + upward trend | Clean |
| `Metrics` | All 11 measures live here | Clean |
| `dim_geography_region_master` | **Deliberately raw. This is the demo sandbox.** | Broken on purpose |

Measures in `Metrics`: Revenue, Cost, Gross Margin, Margin %, Orders, Units Sold,
Customers, Avg Order Value, Discount Given, Revenue PY, Revenue YoY %.

### The four defects planted on purpose

All four are safe to fix live — **none of them are referenced by any visual**, so
the report cannot break while you demo.

1. **Raw table + raw column names** — `dim_geography_region_master` with `GeoKey`,
   `CntryNm`, `RgnNm`, `SubRgnNm`, `PopnCnt`.
2. **Zero descriptions** anywhere in the model — every table, column and measure.
3. **Keys visible and summarizing** — `ProductKey`, `CustomerKey`, `GeoKey` etc.
   are not hidden and will happily sum in a visual.
4. **A missing relationship** — nothing joins geography to `Customer[Country]`,
   so the table is dead weight until you wire it up.

## 3. The live demo — 12 minutes

Prompts are what you say to the agent. Tool names are what it should call.

### Step 1 — Connect and survey (~1.5 min)

> "Connect to the Power BI Desktop instance that's running."

> "List the tables and show me the schema of each one."

`connection_operations` → `ListLocalInstances`, `Connect`
`table_operations` → `List`, `GetSchema`

**Say:** *"It reads the real schema first. Never let an agent rename from memory —
the model may already be half cleaned."*

Point out `dim_geography_region_master` sitting there with nonsense column names.

### Step 2 — Rename for humans (~2 min)

> "Rename `dim_geography_region_master` to `Geography`, and rename its columns to
> business-friendly names — `CntryNm` to `Country`, `RgnNm` to `Region`,
> `SubRgnNm` to `Sub Region`, `GeoKey` to `Geo Key`, `PopnCnt` to `Population`."

`table_operations` → `Rename`, then `column_operations` → `Rename` (each takes a list)

Tables first, so the column operations reference the new table name.

### Step 3 — Descriptions everywhere (~2 min)

> "Add a one-line description to every table, every visible column and every
> measure in this model. Show me the list before you apply it."

`table_operations` / `column_operations` / `measure_operations` → `Update` with a list (transactional)

**Say:** *"This is the single biggest lever on Copilot and Data Agent answer
quality, and it's the work everybody skips because it's boring."*

Hidden keys don't need descriptions — only what a human or an AI will actually see.

### Step 4 — Naming standards (~1.5 min)

> "Rename every table and column to our convention: no `dim_`/`fact_` prefixes,
> spaced Title Case, keys suffixed `Key`. Show me the plan before you apply it."

`table_operations` → `Rename` with a list (transactional)

**Say:** *"A naming standard is normally a wiki page nobody reads and a code review
nobody enjoys. Here it's one prompt applied to sixty objects, consistently."*

Renames trigger engine **formula fixup**, so the measure DAX usually follows on its
own. Usually — check one measure afterwards rather than assuming.

**On synonyms, if asked.** The server won't write them — as of v1.0.0 no tool schema
mentions linguistic metadata or synonyms at all. Say so plainly and point at the
**Synonyms** box in Desktop's Model view. Do not script a synonym prompt into the
demo; it will fail in front of the room.

### Step 5 — Keys, relationships, a new measure (~3 min)

> "Hide every key and ID column across the model and set summarizeBy to None so
> they never sum in a visual."

> "`Geography[Country]` and `Customer[Country]` hold the same values but there's no
> relationship. Create it, one-to-many from Geography to Customer."

> "Add a measure `Revenue per Customer` to the Metrics table. Validate the DAX
> first, then create it, then run it to show me the number."

`column_operations` → `Update` (with a list)
`relationship_operations` → `List`, `Create`
`dax_query_operations` → `Validate`, then `measure_operations` → `Create`, then `Execute`

Points to land:
- `summarizeBy: None` is the fix for the classic *sum of CustomerKey* bug
- Relationships bind by **object**, not by name — renaming a key column doesn't
  break them. Check anyway.
- Validate before Create costs nothing and catches the hallucinated column name

### Step 6 — Make it durable (~2 min) — **do not cut this**

> "None of this is saved yet."

MCP edits live in Power BI Desktop's **memory** only. Close Desktop without saving
and every change is gone — the file on disk still has the old model.

- **A —** Press `Ctrl+S` in Desktop in front of the room, then reopen the `.pbip`
  to prove it loaded from disk.
- **B —** `database_operations` → `ExportToTmdlFolder` at the `*.SemanticModel`
  folder. The exporter writes a **flat** layout; a PBIP expects `database.tmdl`,
  `model.tmdl`, `relationships.tmdl`, `tables/` and `cultures/` under
  `definition/` — move them. Leave `.platform` and `definition.pbism` at the root.

**Closing line:** *"Never tell anyone the model is updated unless you watched it save."*

### Optional stretch — the report layer (if you have 2 spare minutes)

> "Using the Power BI report authoring skill, add a card and a bar chart showing
> Revenue by Region on the Executive Overview page."

```bash
powerbi-report-author validate "ContosoRetail.Report"
```

```bash
powerbi-desktop reload --pid <pid>
```

This is the clean handoff to the skills slides — the model is the MCP's job, the report
layer is the skill's job.

## 4. Rebuilding this artifact from scratch

If you want to demonstrate greenfield creation rather than cleanup, the prompt
sequence that produced this project was:

1. **Model** — "Create a PBIP semantic model for a retail sales star schema: Date,
   Product, Customer, Sales fact, and a Metrics table for measures. Generate the
   data with M expressions so it needs no data source. Add revenue, margin, orders
   and YoY measures."
2. **Design** — the design skill for the page archetypes and palette.
3. **Report** — the authoring skill for the PBIR files, then
   `validate` → `reload` → `screenshot` until clean.

(This was built with Skills for Fabric v0.3.4, when design and authoring were separate skills.
Since v0.3.17 both are modes of one skill, `powerbi-report-cli` — ask for the outcome and it
picks the mode.)

The theme is `ContosoRetail.Report/StaticResources/RegisteredResources/ContosoSignal-*.json`.
Palette: ink `#14182E`, teal `#1F9E96`, blue `#2D5F8B`, amber `#E0A526`, clay `#C0724A`.

## 5. Gotchas found while building this

These cost real time. They are the most useful thing on this page.

1. **`.pbip` `$schema` must be `fabric/pbip/pbipProperties/1.0.0/schema.json`.**
   Any other value and Desktop opens a blank "Untitled" window with an
   *"Issues were found"* dialog. It does not tell you which file until you read it.

2. **The Desktop Bridge pipe only exists when Desktop is launched by the CLI.**
   `powerbi-desktop open <path.pbip>` works; launching `PBIDesktop.exe` directly —
   or double-clicking the file — gives you `NO_BRIDGE` and no reload/screenshot.

3. **`cardVisual` does not render from hand-authored PBIR** in Desktop 2.155
   (26.06). It passes `powerbi-report-author validate` with zero errors and renders
   as an empty box. Confirmed with the bare-minimum template, on a fresh open, with
   no formatting at all. **Use `multiRowCard` with the `Values` role instead** —
   it renders first time and gives you the accent bar via `card.barShow` /
   `card.barColor`. That is what the KPI tiles in this report use.

4. **`padding` on `cardVisual` is a *visualContainerObject*** with `top`/`bottom`/
   `left`/`right` — not an `objects` entry with `topMargin`/`bottomMargin`. The
   skill's card example implies otherwise. Check with
   `powerbi-report-author formatting describe-object <type> <object>` and read `_source`.

5. **Axis and label property names are not what you'd guess.** It's
   `showAxisTitle`, not `titleShow`. Data-label colour is `color`, not `labelColor`.
   `labelDisplayUnits` is a *string* enum (`"1000000"`), not a number.

6. **Donut `labels.labelStyle`** valid value is `Percent of total`, not `Percent`.

7. **`themeCollection.customTheme.reportVersionAtImport` is required** or the whole
   report fails schema validation.

8. **Published PBIR schema versions currently max out at** `visualContainer/2.9.0`,
   `page/2.1.0`, `report/3.3.0`, `pagesMetadata/1.1.0`, `versionMetadata/1.0.0`.
   The skill's cartesian reference suggests `visualContainer/2.10.0` — that URL 404s.

9. **The validator is worth running after every batch.** It caught six real
   property/enum mistakes in one pass. It does **not** catch Gotcha 3 — only a
   Desktop render does.

10. **Memory.** Power BI Desktop plus `msmdsrv` plus the Node CLIs need headroom.
    Below roughly 1 GB free the CLIs fail with `VirtualAlloc failed`,
    `fork: Resource temporarily unavailable`, or `Starting the CLR failed` — which
    look like tool bugs but are just RAM.

## 6. If the live demo goes wrong

| Symptom | Do this |
|---|---|
| MCP can't see Desktop | Reopen the PBIP via `powerbi-desktop open`; the port changes each launch |
| Connection times out mid-demo | Re-run `ListLocalInstances` + `Connect` |
| Rename rejected | `Measures` is a reserved table name — this model uses `Metrics` |
| A measure breaks after a rename | `measure_operations` → `Update` with the corrected expression |
| Visuals go blank | You renamed something the report binds to. Undo, or switch to the screenshots |
| Everything stalls | Show `shots/*.png`, talk through the boundary slides, move on |

**The safest recovery is always:** stop the live run, show the screenshots, and
keep talking. The content of the session is the boundary — not the typing.
