# Fabric & Power BI MCP — Skills for Fabric

Companion repo for the Fabric Community blog series **Power BI + Fabric MCP in practice** and the
30-minute Fabric User Group session. It has everything you need to run the demo yourself: a
self-contained Power BI project, the deck, the runbook, and **`powerbi-synonyms`**, a skill that
adds Q&A and data-agent synonyms to a semantic model. That's the one AI-readiness setting that
neither the Power BI Authoring MCP server nor Microsoft's official skills will write.

## Quick start

**You need:** VS Code with GitHub Copilot (Agent mode), Node.js 18+, and Power BI Desktop.

1. **Install the Power BI Authoring MCP server.** In VS Code's Extensions view, search for
   `powerbi-modeling-mcp` and install **Power BI Authoring MCP Server** (Microsoft).
   Setup guide: [learn.microsoft.com: Power BI Authoring MCP](https://learn.microsoft.com/power-bi/developer/mcp/power-bi-authoring-mcp).
   Check it's running with **Command Palette → `MCP: List Servers`**.
2. **Clone this repo and open the folder in VS Code.** The `powerbi-synonyms` skill is in
   `.github/skills/`, so it's installed at project level as soon as the folder is open. Type
   `/skills` in the chat box to see it.
3. **Optional: add Microsoft's Skills for Fabric** (`semantic-model-authoring`, `powerbi-report-cli`
   and more) from [microsoft/skills-for-fabric](https://github.com/microsoft/skills-for-fabric). If
   you copy skills by hand from the ZIP, copy `common/` next to your skills folder too, or their
   shared links break.
4. **Open `demo/ContosoRetail.pbip`** in Power BI Desktop and follow [`demo/DEMO-GUIDE.md`](demo/DEMO-GUIDE.md).
   **The first time, the visuals are blank:** the repo ships the model definition but not Desktop's
   data cache. Click **Refresh** (the data is generated by M in seconds, no source needed). On one
   low-memory machine the first full refresh reported *"A cyclic reference was encountered during
   evaluation"* on a different table each attempt; clicking **Refresh now** again loaded everything.

## Try the synonyms skill

With the demo model open in Desktop (or closed, for PBIP mode), ask Copilot:

> Our data agent doesn't understand words like turnover, AOV or client. Add business synonyms to
> the ContosoRetail semantic model for the main measures and the Customer table.

The agent picks up `powerbi-synonyms`, drafts a map, and **waits for your approval**. Then it runs a
dry run, writes, and verifies every term. You can also run the script yourself:

```bash
# PBIP mode (Desktop closed): needs only Node
node .github/skills/powerbi-synonyms/scripts/set-synonyms.js --model demo/ContosoRetail.SemanticModel --input .github/skills/powerbi-synonyms/examples/contoso-synonyms.json --dry-run

# Live mode (model open in Desktop): needs Windows PowerShell + the TOM assemblies
node .github/skills/powerbi-synonyms/scripts/set-synonyms.js --server localhost:<port> --input map.json --mirror demo/ContosoRetail.SemanticModel
```

Drop `--dry-run` to apply. Tests: `node --test ".github/skills/powerbi-synonyms/tests/*.test.js"`.
How it works, and why each rule exists, is in [`SKILL.md`](.github/skills/powerbi-synonyms/SKILL.md)
and Part 2 of the blog.

## Try the standards skill

`contoso-model-standards` is an example of **layering your team's rules on top of Microsoft's
`semantic-model-authoring`** instead of editing it. The rules live in
[`standards.json`](.github/skills/contoso-model-standards/standards.json): change `keySuffix` to
`"Key"` and the whole skill follows. With the demo model open in Desktop, ask:

> Apply our Contoso model standards to the ContosoRetail semantic model. It's open in Power BI Desktop.

The agent saves, runs the read-only checker, shows a plan, waits for approval, renames and hides the
keys through the Power BI Authoring MCP server, and checks again. Run the checker yourself with
`node .github/skills/contoso-model-standards/scripts/check-standards.js --model demo/ContosoRetail.SemanticModel`.
